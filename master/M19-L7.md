# M19-L7 – Computational Records, Convergence and Scientific Verification {#L7}

**Course area:** M19 – Bachelor: Advanced Experimental Methods and Research Practice

**Level:** Bachelor

**Prerequisites:** M17: numerical methods and stability; M19-L4: residuals; M19-L6: data provenance. [Previous lesson](M19-L6.md).

**Learning objective:** Distinguish numerical verification from experimental validation and test step-size dependence.

## Question and Model {#S1}

A scientific computational run needs a traceable version chain from raw data and source code to results. Verification asks whether the numerical scheme solves the stated equations adequately; validation asks whether those equations represent the physical system. A convergent solver can solve the wrong physical model with impressive precision. Analytical limits, independent implementations, experimental controls and sensitivity analyses therefore serve distinct purposes.

## Equations and Assumptions {#S2}

A simple verification test approximates the derivative of $f(x)=\sin x$ at $x=0$ via the central difference
$$
D_hf(0)=\frac{\sin(h)-\sin(-h)}{2h}=\frac{\sin h}{h}.
$$
Since $f'(0)=1$ and $\sin h=h-h^3/6+O(h^5)$, we obtain $D_hf(0)=1-h^2/6+O(h^4)$. Halving $h$ should reduce the leading error by approximately four in the asymptotic regime. The rule fails when other error sources such as roundoff dominate.

## Worked Example and Diagram {#S3}

At $h=0.4$, the approximation is $D_h\approx0.9735459$ with absolute error $e_h\approx0.0264541$. At $h=0.2$, $D_h\approx0.9933467$ with $e_h\approx0.0066533$. Their ratio is about $3.976$, consistent with second-order convergence in this range. The plot compares the calculated errors against the step size with a theoretical reference curve. These are exact mathematical test values, not observed instrument errors.

## Self-assessment {#S4}

### Exercises

1. What is the difference between verification and validation?
2. How should the leading central-difference error change when $h$ is halved?
3. Name three entries that a numerical run record must include.

### Solutions

1. Verification checks the equations are solved; validation checks their appropriateness for reality.
2. In the asymptotic regime it falls to roughly one quarter.
3. For example code version, input checksum and grid spacing; add random seed for stochastic methods.

## Limits and Quality Control {#S5}

Record code version, dependencies, parameters, units, random seed when applicable, platform and data checksums. Run convergence and stability tests on the actual computational pathway, not only on the final published figure. Discuss numerical uncertainty separately from measurement and model uncertainty. Distribution also requires resolving licences, access and retention rules. This worked numerical check is evidence for one approximation, not certification of an entire research project.

## Summary and Outlook {#S6}

A traceable run combines versioned inputs with explicit convergence tests.
